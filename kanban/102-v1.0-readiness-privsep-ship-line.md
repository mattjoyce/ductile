- [x] **DECISION (Matt, 2026-06-08): YES — the Mac M1 IS a v1.0 production host.**
      → [[95-privsep-launchd-and-live-rollout]] (launchd enforce) is **IN SCOPE for v1.0**. All 5

      - **Tradeoff accepted:** launchd has no cap-only model → macOS enforce runs as a **root
        LaunchDaemon** (Linux runs non-root + `CAP_SETUID/SETGID`). The Mac cannot reproduce the
        cap-only hybrid trust-tier shape; root-on-Darwin is mitigated by SIP/`task_for_pid` gating
        but is still root. Documented as the known macOS posture, not papered over.
      - **#95 is deploy+verify, not engine work:** mechanism (`process_unix.go` uid-drop,
        `fsreconcile_unix.go`, `sidedoor_audit_unix.go`) already builds/runs on Darwin. Missing =
        (1) `deploy/launchd/` root LaunchDaemon plist, (2) `dscl`/`sysadminctl` account provisioning
        (no sysusers.d on macOS), (3) **port the wall/negative/capdrop proof suite off `_linux_test.go`
        and run it GREEN on Darwin** (the #101 anti-footgun applied to ourselves), (4) update
        `docs/MACOS_INSTALLATION.md`.
      - **Note (2026-06-07):** the privsep *mechanism* compiles + runs on macOS (Unix uid-drop +
        fs-reconcile; enforce reachable as **root** since launchd has no cap-only model); what #95
        adds is the root-LaunchDaemon + macOS account provisioning + running the wall/negative suite
        on Darwin (never verified there). So #95 is *deploy + verify*, not *build*.
