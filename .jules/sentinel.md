## 2026-06-20 - Fix Overly permissive CORS configuration / wildcards
**Vulnerability:** The API server's CORS middleware did not properly support the `*` wildcard origin when configured in `AllowedOrigins`. Instead, it treated `*` as a literal origin string. If a developer intended to allow all origins by setting `*`, it would fail to match any real origin like `https://example.com`. To properly fix this, allowing any origin must be done without setting `Access-Control-Allow-Credentials: true`, as CORS specifications forbid credentialed requests when the allowed origin is a wildcard.
**Learning:** Security features like CORS have complex rules (e.g., wildcards vs. credentials) that can lead to misconfigurations if not explicitly handled in the middleware logic.
**Prevention:** Always write dedicated unit tests for edge cases like wildcard configuration and cross-reference them with security specifications (like CORS RFCs) to ensure intended security constraints are upheld.
